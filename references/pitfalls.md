## 1. `0x800A9D00` Import 意外

- **现象**：写回时 `Import` 抛 `0x800A9D00`，或提示临时文件不可见。
- **原因**：Python 沙箱 `temp` 与隐藏 Excel 进程不在同一可见范围。
- **处理**：临时导入目录放到工作簿同目录 `.vba-import-*`，整轮结束删除。
- **禁止**：不要把源码直接留在 `%TEMP%` 里让 Excel 读。

## 2. `50289` / 工程受密码保护

- **现象**：`VBProject` 能读名字，碰 `VBComponents` 报“该工程已被保护”。
- **原因**：VBA 工程设置了密码保护，或工作簿已被别的 Excel 实例占用。
- **处理**：先在 Excel 里解除工程密码保护；确认没有另一个实例占用；重新运行 `sync.py plan` 看模式。
- **禁止**：不要另开副本硬写；不要反复重试同一个受保护工程。

## 3. `COM_CONTEXT` 连不上已打开的工作簿

- **现象**：工作簿明明已打开，`push` 却连不上，提示 `COM_CONTEXT`。
- **原因**：Excel 在另一用户/另一桌面会话，或 ROT 里有多个实例，连到了错误实例。
- **处理**：按项目路径匹配实例；仍失败就让用户在当前会话里打开；看 `agent.py probe` 的“已打开/工程”列。
- **禁止**：工作簿已打开且有未保存改动时，禁止转磁盘写回。

## 4. `VBE_PROTECTED`（工程密码保护 / AccessVBOM 未开）

- **现象**：读不到 `VBProject`，或 `AccessVBOM` 未开。
- **原因**：VBA 工程设置了密码保护；信任中心未勾“信任对 VBA 工程对象模型的访问”。
- **处理**：解除工程密码保护；在 Excel 信任中心勾选；重新运行 `doctor --json`。
- **禁止**：自动流程不要改注册表/信任中心/`VBAWarnings`/`AccessVBOM`。

## 5. 宏不可用 / 被禁用（1.6 归 `RUN_FAILED`）

- **现象**：`run` / `assert` 报宏不可用、被禁用，或工程有编译错误导致全部宏不可用。
- **原因**：用户手工会话里，信任中心宏设置、文件来自网络被拦、信任位置未配置；也可能是宏名对不上、模块与过程重名、工程存在编译错误。
- **处理**：把工作簿目录加入信任位置，或让用户手动启用宏；核对宏名（必要时写成 `模块.过程`）并回 VBE 修掉编译错误后再运行 `run`。
- **禁止**：不要用脚本改安全设置绕过。

> **1.6 收口规则**：缺宏 / 禁用宏 / 业务报错统一报 `RUN_FAILED`（`stage=run`/`assert`），旧细分码
> `MACRO_NOT_AVAILABLE` / `MACRO_DISABLED` 已从错误码枚举撤销，缺宏与禁用宏的区分信息只出现在 `hint` 文案；
> 不恢复独立分流码（B3 复核维持已接受设计差异，见 `backlog-1.7.md`）。
> **自动化会话的差异**：`run --isolate` / COM 起的实例 `AutomationSecurity=Low`，宏会被放行，与信任中心无关。

## 6. `TARGET_OPEN` 隔离模式撞已打开工作簿

- **现象**：`run --isolate` 报目标工作簿已打开。
- **原因**：隔离模式要求独占打开，已打开实例会抢文件锁。
- **处理**：关闭那个 Excel 窗口，或去掉 `--isolate` 用已打开会话。
- **禁止**：不要强关用户窗口；不要伪造“已关闭”。

> **1.6.5 规则 · `COM_CONTEXT` 时隔离模式也不启动**：隔离预检只放行 `NO_EXCEL` / `TARGET_NOT_OPEN`；目标实例卡在弹窗 / 受保护视图 / 权限不同的会话（`COM_CONTEXT`）时，预检连不上这个实例，就不敢另开副本去抢文件锁，隔离副本同样不启动。hint 列三类成因与下一步，suggested_command 给可复制的 `run --project … --macro … --isolate --apply`；JSON 模式下 hint / suggested_command 只进信封字段，不混进 stdout。

## 7. `Attribute` / CRLF 导致回读不一致

- **现象**：`postcheck` 报正文不一致，但肉眼看一样。
- **原因**：导出头/过程级 `Attribute`、CRLF/LF、行尾空白、关键字大小写差异。
- **处理**：统一走 `strip_export_header` + `norm_code_lines` + `fold_lines` 指纹；不要按字节比对。
- **禁止**：不要为了过校验去改源码换行或删 `Attribute` 以外的内容。

## 8. `.frx` 缺失，窗体设计丢失

- **现象**：`.frm` 能导入，但控件/属性丢失。
- **原因**：同名 `.frx` 没跟着复制，或源码目录只提交了 `.frm`。
- **处理**：`gbk_import_copy` 会成对复制 `.frm` + `.frx`；git 里两者必须一起提交。
- **禁止**：不要单独导入 `.frm`。

## 9. ROT 多实例，连到“当前活动”错实例

- **现象**：`probe`/`push` 看到的工作簿不是目标工作簿，模块数对不上。
- **原因**：多个 Excel 实例同时开着，按“活动实例”取会取错。
- **处理**：按工作簿完整路径匹配；匹配不到就报 `COM_CONTEXT`，让用户确认。
- **禁止**：不要用 `GetActiveObject` 随便抓一个实例就写。

## 10. 前缀模块 `xxx1` 抢名

- **现象**：写回后工程里出现 `表格工具1`，原模块还在。
- **原因**：`Remove` 提交延迟，紧接着 `Import` 同名牌，VBE 自动补序号。
- **处理**：`.bas/.cls` 原地改正文，不 Remove；必须 Import 时走 `import_component` 改名/重试；`postcheck` 会拦。
- **禁止**：不要手工把 `xxx1` 当成新模块提交。

## 11. 源码预检拦下（`SOURCE_PREFLIGHT`）

- **现象**：`push` 还没碰 Excel 就失败，`errors[0].code=SOURCE_PREFLIGHT`、`stage=preflight`。
- **原因（硬错误）**：源码目录不存在、没有可写模块、同目录模块重名、非占位壳 `.frm` 缺同名 `.frx`、`VB_Name` 与文件名不一致、非文档 `.bas/.cls` 正文为空、`.cls` 缺 `VERSION 1.0 CLASS`、单语句续行超过 24 行、源码读不出。软提醒（BOM / CRLF / 缺 `Option Explicit` / 末行续行截断 / 跨目录同名 / 类模块 `Me.` 引用私有字段）只汇总，不阻断。
- **处理**：按提示补 `.frx`、改文件名或文件头、补正文/编码、拆分长续行后重新运行；预检失败不会打开工作簿、不会产生新备份。
- **禁止**：不要绕过预检或手工改工程“先写进去再说”。

## 12. 回读校验失败（`POSTCHECK_FAILED`）

- **现象**：写回完成但未保存，`errors[0].code=POSTCHECK_FAILED`，明细带源码/VBE 行数与首个差异行。
- **原因**：写进 VBE 的正文与源码指纹不一致（编码、截断、真正的正文差异）。过程级 `Attribute` 行和 VBE 末尾自动补的 `()` 占位已由回读端按写入端规则忽略，不再算失败。
- **处理**：修源码/编码后重新运行；本次结果不保存、不自动回滚。
- **禁止**：不要手工 Ctrl+S 保存这次半成品。

## 13. 单语句续行超过 24 行（`SOURCE_PREFLIGHT`）

- **现象**：`push` 在写回前报 `SOURCE_PREFLIGHT`，提示“单语句续行超过 24 行”，带文件和起始行号；VBE 导入时才报“续行太多”。
- **原因**：VBA 一条逻辑语句最多 24 个续行（25 个物理行）；工具生成的拼行代码容易越界。
- **处理**：拆成多条语句、把参数先赋给局部变量，或改用数组/字典批量调用。
- **禁止**：不要靠删空格、把 `_` 换成别的字符绕过；这会让语句变成语法错误。

## 14. `.cls` 缺 `VERSION 1.0 CLASS` 类头（`SOURCE_PREFLIGHT`）

- **现象**：`push` 预检报“类模块缺 VERSION 1.0 CLASS 类头”，VBE 导入时才报“缺少 VERSION 1.0 CLASS”。
- **原因**：`.cls` 被手工编辑/复制时删掉了导出头，或从 `.bas` 直接改名。
- **处理**：在文件第一行补 `VERSION 1.0 CLASS`，再按导出格式保留 `BEGIN`/`MultiUse`/`END` 与 `Attribute VB_*`。
- **禁止**：不要把标准模块 `.bas` 直接改名成 `.cls`；不要只补 `Attribute VB_Name` 就当成类模块。

## 15. 类模块 `Me.` 引用私有字段（软提醒）

- **现象**：预检提醒“类模块用 Me. 引用私有字段”，不阻断写回；VBE 编译/运行时才暴露。
- **原因**：私有字段被 `Me.` 当公开成员用，跨版本/跨工程时容易编译不过；外部也无法通过 `Me.` 访问私有成员。
- **处理**：类内直接写字段名；要给外部用就改成 `Public` 属性过程（`Property Get/Let`），不要靠 `Me.` 绕过可见性。
- **禁止**：不要把私有字段改成 `Public` 只为让 `Me.` 编译通过；先确认调用方是否真需要访问。

## 16. H05a 报了三条关闭加速，但代码确实成对还原

- **现象**：`indicators` 的 H05a 仍报 `ScreenUpdating=False / Calculation=Manual / EnableEvents=False`，而下方已有还原。
- **原因**：项目侧直接关闭加速，H05a 默认只放行“块上方三行内有 `[加速例外]`”或公共库 `表格工具.安全执行`。
- **处理**：优先改用 `表格工具.安全执行`；确需手写时在关闭块上方三行内加 `[加速例外]` 注释，再运行 `audit.py indicators --json`。
- **禁止**：不要为了消警告删掉还原行，也不要把标记写到块外很远的位置。
