# 变更标准（vba-workbench）

> 适用范围：本仓库的脚本、命令、规则、文档、测试、发布链和安装副本。
> 目的：把“想到就改”收敛为“先定义、再评审、后执行、可回滚”，避免命令契约、VBA 语义和发布状态反复漂移。
> 配套：技术硬规则见 [`sync-maintain.md`](sync-maintain.md) §6；待办状态见仓库根 `TODO.md`（不随安装包交付，安装副本里读不到）；能力整合方案见 [`vba-tool-integration.md`](vba-tool-integration.md)。

## 1. 变更分级

| 级别 | 类型 | 例子 | 最低要求 |
|---|---|---|---|
| D0 | 纯文档 | 术语、说明、待办、评审标准 | 文档链接可解析；不改版本、不打包 |
| D1 | 内部重构 | 函数拆分、命名、日志措辞，外部行为不变 | 定向测试 + 语法检查；命令表不变 |
| D2 | 行为变更 | 新命令、新参数、新 JSON 字段、新错误码、规则变化 | 先评审；命令表 + 文档 + 测试 + 兼容说明 |
| D3 | 发布 | 版本号、zip、安装副本、public 快照 | D2 全部门禁 + doctor + 全量回归 + 脱敏 + 校验和 |

**判断口径**：用户能观察到的输出、退出码、文件副作用、命令参数变化，至少是 D2；只改内部实现且测试证明行为不变，才是 D1。

## 2. 改前流程

1. **先说清楚**：要解决什么问题、准备怎么改、会影响哪些命令/文件/数据；不要静默开工。
2. **先搜现成方案**：新问题先查官方文档、同类工具、现有 issue；不要只盯着代码反复试错。
3. **选最小改动**：能加只读检查就不改写回；能加可选参数就不改默认行为；能复用 toolkit 就不新写一套。
4. **登记待办**：在 `TODO.md` 建编号，写状态、范围、验收、风险；未批准项不动代码。
5. **确认边界**：明确“不做”列表；不确定的数据写入、引用修改、批量删除，先停下来要确认。
6. **再动手**：批准后才建分支/改代码；每次只推进一个可验收的小批次。

## 3. 设计与接口标准

1. **命令白名单**：动词必须在 `SPECS` 登记；未知动词退出 2，不能被当成项目名。
2. **参数**：沿用 `--project` / `--module` / `--macro` / `--all-project` / `--json` / `--apply`；不新增位置参数。
3. **写操作**：默认只预览；`--apply` 才执行；禁止恢复 `--yes`、`--dry-run`、`--clean` 等旧开关。
4. **JSON**：stdout 恒一行 `{ok, action, details, errors, elapsed_ms, ts, stats, exit_code}`；`errors[]` 每项含 `code/stage/message/hint/suggested_command/retryable`。
5. **退出码**：0 成功；1 业务失败；2 用法错；3 只读体检仅警告；130 用户中断。不要为新功能另造一套。
6. **错误码**：先登记再使用；同一类失败只用一个码，细分信息放 `hint`；不要用报错文本当协议。
7. **只读默认不碰 Excel**：能在 `src`/OOXML 上做的检查，不要启动 Excel；需要 COM 的必须走 `excel`/`session` 基础函数。
8. **串行**：同一 Excel 实例不并行写回；`watch` 与 `push` 不同时写同一个工作簿。
9. **不重复实现**：新命令优先复用 `toolkit` 的会话、备份、预检、渲染、进度；features 之间不互相 import。

## 4. 数据安全标准

1. **写前备份**：写工作簿前必须备份；批量写回逐工作簿备份；备份失败不得继续。
2. **引用保护**：默认 References 不删除、不重排；新增/删除/同步引用必须单独批准、先预览、保留默认引用。
3. **不覆盖原件**：发布工作簿、导出快照、格式化输出默认写新文件；覆盖原件必须显式 `--apply` 且有备份。
4. **可回滚**：写回失败按现有 `--rollback-on-fail` 语义处理；不能保证回滚的操作，先不做。
5. **最小副作用**：不操作未登记工作簿；不改业务数据；不自动清理用户文件；不把临时文件留在工作簿目录。
6. **不静默降级**：依赖缺失、解析失败、权限不足必须报明确错误或 warning；不能把“没检查”说成“通过”。

## 5. VBA 语义标准

1. **源码格式**：`.bas/.cls/.frm` 用 UTF-8 无 BOM + LF；GBK 只出现在 VBE 交换边界。
2. **标识符大小写**：跟随工程既有形态；新名字按 VBE 规则；禁止批量改大写再 `push` 试图纠正。
3. **模块名与文件名**：一律用 `repo.module_name_of()`；文档模块文件名带工作表名，不能拿 `stem` 直接比模块名。
4. **`.frx`**：必须与 `.frm` 同目录同名；二进制字节差异不算正文差异。
5. **文档模块**：不能 `Remove`；只能改代码行；写回不新建文档模块。
6. **格式化**：不碰字符串、注释、标识符大小写和行续行语义；只做空白/缩进类安全变换。
7. **公共库**：项目目录只留占位壳；公共库与项目同名冲突没有自动方案，不擅自合并。

## 6. 测试与门禁

### D0 文档

- 检查 Markdown 链接目标存在。
- 检查 `TODO.md` 编号不重复、状态与方案文档一致。
- 不要求全量回归。

### D1 内部重构

```powershell
python -m compileall -q scripts tests
python -m unittest tests.test_xxx
```

- 命令表未变时不必重新生成；若 `SPECS` 变了，必须跑 `tests/tools/gen_commands_md.py`。

### D2 行为变更

1. 定向单测：正例 + 反例 + 错误路径。
2. `python tests/tools/gen_commands_md.py`（命令面变化时）。
3. `python -m unittest tests.test_gen_commands_md tests.test_version_consistency`。
4. 全量回归：`python -m unittest discover -s tests`；当前基线 626 通过 / 1 skip，新增用例后更新基线说明。
5. `python scripts/sync.py doctor --json`，5/5 项目通过。
6. 涉及真实 Excel 的行为，补 `tests/MANUAL.md` 或 golden；不能自动构造的如实登记 `not_run`。

### D3 发布

在 D2 基础上增加：

1. `VERSION`、`SKILL.md` metadata、`CHANGELOG.md` 三处一致。
2. `python scripts/sync.py scrub --json`，0 命中。
3. 打包、`SHA256SUMS.txt`、`latest.txt`。
4. 安装副本逐文件哈希对齐；`.installed.json` 刷新。
5. public 快照重建并脱敏；不包含 `tests/`、`TODO.md`、`.lab`。
6. GitHub 发布记录写清版本、包哈希、public 提交。

## 7. 文档与版本

1. **`SKILL.md` 只放触发、核心流程和边界**；细节进 `references/`，且只从 `SKILL.md` 链接一层。
2. **`references/commands.md` 是 manifest 生成物**，禁止手改；改命令先改 `SPECS`，再生成。
3. **`TODO.md` 是唯一待办入口**；历史报告只做证据，不再当执行清单。
4. **`CHANGELOG.md` 只记对外可见行为**；内部重构写提交信息，不塞日志。
5. **版本以 `VERSION` 为准**；历史版本号只作记录，不作为现状。
6. **安装副本不手工改**：先改源仓库，再走安装/升级流程；文档改动也要刷新 `.installed.json`。
7. **文档脱敏**：真实用户名、机器名、业务工作簿名、客户名、经营数字不进发布包。

## 8. 第三方能力整合标准

1. **只借鉴行为，不复制源码**：尤其是 MZ-Tools 等商业工具；Rubberduck 等开源项目也要先核许可证。
2. **不新增硬依赖**：优先复用标准库/现有依赖；新依赖必须可选、可降级、有明确错误码。
3. **适配层隔离**：外部工具格式（`vba-project.json`、`xlflow.toml`）通过 adapter/序列化层接入，不侵入核心模型。
4. **默认关闭**：MCP、安全扫描、格式化、发布工作簿等新增能力，默认不改变现有流程；用显式参数开启。
5. **只读先行**：先做 list/check/report，再评估 write/sync/apply；写操作单独评审。
6. **不做编辑器**：不引入 LSP、补全、跳转、重命名、VBE 调试、Control Explorer；这些交给专门工具。

## 9. 评审清单

每次 D2/D3 变更前逐项打勾：

- [ ] 目标和“不做”范围已写清楚。
- [ ] 命令/参数/JSON/退出码已定义，未破坏现有契约。
- [ ] 写操作默认预览，`--apply` 才执行，且有备份/回滚。
- [ ] References、文档模块、公共库、`.frx`、大小写规则未被破坏。
- [ ] 正例、反例、错误路径都有测试；不能自动测的已登记 manual/golden。
- [ ] 命令表、`SKILL.md`、`references`、`TODO.md` 已同步。
- [ ] 版本/CHANGELOG 只在对外可见行为变化时更新。
- [ ] 安装副本与源仓库一致，`.installed.json` 已刷新。
- [ ] 发布前 `doctor`、全量回归、`scrub` 全绿。
- [ ] 变更说明能让下一个人只看文档就复现。

## 10. 停止条件与汇报

**立即停止并汇报的情况：**

- 没有批准就要求改行为；
- 目标工作簿/项目不明确，或可能写错文件；
- 需要删除/覆盖用户数据，且没有备份；
- 测试失败、doctor 失败、依赖/许可证不明；
- 超时、卡死、Excel 弹窗无法自动处理（按既有策略处理，不反复重试）；
- 发现文档与代码、版本与安装副本不一致。

**汇报节奏：**

1. 改前：问题、改法、影响面、验收方式。
2. 每完成一个阶段：已完成什么、验证结果、下一步。
3. 发现问题：先记录，不中断当前任务；最后统一汇总。
4. 结束时：改了哪些文件、跑了哪些门禁、哪些没跑及原因。
